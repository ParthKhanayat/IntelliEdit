# IntelliEdit — 30% Milestone Evaluation Guide

## 1. Milestone Status: Is this 30%?
**Yes, absolutely.** This represents an ideal **30% – 40% milestone** (Phase 1 evaluation) for a compiler design course:

### What is Fully Functional & Real
- **Full-Stack Pipeline**: React + Monaco Editor communicating in real-time with the Python (FastAPI) backend.
- **Phase 1: Lexical Analysis**: Real tokenization powered by Tree-Sitter (extracting identifiers, keywords, symbols, literals).
- **Phase 2: Syntax Analysis (Parsing)**: Real Abstract Syntax Tree (AST) construction parsing C source code in real time into an expandable JSON/visual tree hierarchy.
- **IDE Autocomplete Integration**: Monaco Editor autocomplete hooks connected directly to the backend autocomplete endpoint.

### What is Stubbed / Prototype Mocked (Next Milestones)
- **Phase 3: Semantic Analysis** (Type checking, scope validation).
- **Phase 4: Intermediate Code Generation (IR)** (LLVM IR).
- **Phase 5 & 6: Optimization & Target Code Generation** (x86 Assembly).
- **AI Optimization Suggestions**: Endpoints in `ai_engine.py` currently return structured prototype fixtures, ready to be wired up with the live Google Gemini API.

---

## 2. Recommendation on Placeholder Values
**Definitely KEEP the default placeholders and mock values.**

- **No Awkward Blank Screen**: Starting with an empty editor and empty panels makes the project look broken or unfinished.
- **Immediate Visual Impact**: The moment the app opens, the professor immediately sees:
  - Working C boilerplate (`main.c` with `#include <stdio.h>...`).
  - Sleek Monaco editor with dark glassmorphism theme.
  - Active lexical tokens and parsed AST tree nodes pre-rendered.
- **Seamless Live Demo**: You can demonstrate the features immediately without spending time typing boilerplate code. You can then modify the code on the fly to show that the AST and tokens update dynamically.

You can use the following talking points for your presentation:

>

> 2. ***IDE & Autocomplete Engine***: *We embedded Monaco Editor with custom dark glassmorphism styling, wired directly to our FastAPI AST engine for autocompletion.*
> 3. ***Compiler Pipeline Wireframe***: *The downstream phases (Semantic Analysis, IR generation, Code Optimization, and Target Assembly) along with AI suggestions currently use prototype demonstration fixtures in the UI, which will be connected dynamically in the upcoming 60% and final project phases."*

## 4. Live Demo Flow
1. **Show Default State**: Open `http://localhost:5173` to show the editor pre-loaded with `main.c`.
2. **Show Compiler Processes**: Click the **Compiler Processes** tab to reveal:
   - **Lexical Analysis**: Live tokens generated by Tree-Sitter.
   - **Syntax Analysis**: Expandable AST tree nodes representing the parsed C syntax.
3. **Show Live Updates**: Add a new function or variable (e.g. `int x = 10;`) to demonstrate that the AST and tokens update live in response to edits.
4. **Show Autocomplete**: Type `print` or `for` to demonstrate the custom autocomplete suggestions provided by the backend.
5. **Show Roadmap**: Point to the AI Suggestions tab and downstream compiler phases to explain what will be developed next.
